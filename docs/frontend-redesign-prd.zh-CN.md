# Nega_Yuna 前端体验重构 PRD

版本：v2.0  
日期：2026-05-16  
项目：Nega_Yuna 定制版  
当前核心场景：Rokid 海外商务英语会谈训练  
文档类型：前端体验重构 / 产品信息架构 / 可扩展场景框架 PRD  
关联文档：`docs/rokid-overseas-meeting-coach-prd.md`

## 1. 文档目的

当前网站已经具备较完整的功能：材料上传、实时语音练习、准备卡片、表达库、异议库、复盘、进步追踪、模型配置等。但功能被平铺在多个页面中，用户首次进入时不容易知道应该从哪里开始，也不容易形成稳定的练习闭环。

本 PRD 的目标不是重新定义业务方向，而是在现有产品能力基础上，对网站的前端体验、信息架构、核心流程和可扩展能力进行重构，使它从“功能集合”升级为“低门槛、强主线、可持续学习的 AI 口语教练”。

本 PRD 用于指导后续开发，不直接修改现有后端架构，但会提出必要的数据结构、接口和前端状态要求。

## 2. 重构背景

### 2.1 当前问题

1. 一级模块过多，用户容易把网站理解为工具箱，而不是练习产品。
2. 首页没有足够强的主任务，用户不知道今天应该先做什么。
3. `Practice`、`Materials`、`Objection Bank`、`Phrasebook`、`Progress` 之间缺少清晰的学习闭环。
4. 实时对话页更像功能测试界面，不像自然的语音通话体验。
5. 材料上传偏一次性，上传后没有沉淀为长期上下文。
6. 复盘结果没有足够驱动下一次练习。
7. 当前定制化很强，但缺少面向未来其他英语练习场景的模块化框架。
8. 中文用户操作时，需要中文标题、中文提示和更轻量的引导。

### 2.2 重构机会

产品最有价值的不是“有多少功能”，而是能否帮助用户完成一个稳定循环：

```text
打开网站 -> 知道今天练什么 -> 快速进入对话 -> 得到明确复盘 -> 保存有用表达和记忆 -> 下一次练得更准
```

因此，重构重点应从“页面数量”转为“练习闭环”。

## 3. 产品定位

### 3.1 v2 产品定位

Nega_Yuna 是一个会记住用户材料、表达习惯和长期弱点的 AI 英语口语教练。第一阶段聚焦 Rokid 海外商务会谈，帮助用户基于真实材料完成客户沟通演练、异议处理、表达升级和复盘。

### 3.2 一句话描述

每天打开后，系统直接告诉你今天最值得练什么；你可以基于客户材料和 AI 客户实时对话，结束后获得可复习、可沉淀、可用于下一次训练的复盘结果。

### 3.3 产品设计北极星

1. 用户 5 秒内知道网站能帮她做什么。
2. 用户 30 秒内可以开始一次有效练习。
3. 每次练习控制在 8-15 分钟内形成闭环。
4. 每次复盘都能沉淀至少 1 条表达、1 个弱点或 1 条记忆。
5. 下一次练习必须比上一次更懂用户。

## 4. 目标用户

### 4.1 当前核心用户

Rokid 智能眼镜企业海外销售与解决方案人员。

### 4.2 核心任务

1. 面向海外客户介绍 Rokid 产品和解决方案。
2. 重点回答客户关于产品应用场景、优点缺点、与其他产品的差异点、产品详细参数、适配边界和真实落地方式的问题。
3. 回答客户关于部署、隐私、安全、成本、集成、试点和 ROI 的问题。
4. 把产品功能、技术参数和方案能力转换为客户价值。
5. 在英文商务会谈中更流畅、更自然、更有推进力。
6. 复盘自己的表达问题，并形成个人表达库。

### 4.3 用户能力假设

1. 能阅读英文材料，但口头表达不够稳定。
2. 能说完整句子，但在压力、追问和异议场景下容易卡住。
3. 更需要“真实会谈陪练”而不是传统英语课程。
4. 对复杂产品界面耐心较低，希望打开后能直接练。

## 5. 重构目标

### 5.1 业务目标

1. 提高用户开始练习的转化率。
2. 提高单次练习完成率。
3. 让材料、表达、复盘和记忆形成闭环。
4. 让产品从 Rokid 定制版本扩展到多场景英语训练平台。

### 5.2 体验目标

1. 首页只突出一个主任务：今天该练什么。
2. 练习创建流程从配置表单改为轻量引导。
3. 实时对话页呈现为自然的通话界面。
4. 复盘页先给 30 秒可读结论，再提供详细分析。
5. 所有页面减少说明文字，更多使用可操作卡片和明确按钮。
6. 一级导航控制在 4 个核心模块内。

### 5.3 技术目标

1. 保留现有路由和接口的可用性，降低一次性重构风险。
2. 前端引入场景包配置层，使 Rokid 商务场景成为第一个 scenario pack。
3. 新增记忆数据模型和记忆调用策略，支持长期个性化。
4. 前端组件拆分清晰，便于后续扩展不同练习场景。

## 6. 非目标

1. 本阶段不做多人团队管理后台。
2. 本阶段不做真实 CRM。
3. 本阶段不做正式课程售卖、支付和会员系统。
4. 本阶段不要求移动 App，只做移动端友好的响应式 Web。
5. 本阶段不永久保存原始音频，除非用户未来明确开启。
6. 本阶段不把所有历史数据一次性迁移成复杂知识图谱。

### 7.1 新一级导航

一级导航从当前的 7 个模块收敛为 4 个主模块：

```text
今日练习
客户材料
表达库
复盘
```

辅助入口：

```text
设置
场景切换
隐私与记忆管理
```

### 7.2 导航映射

| 当前模块 | v2 模块 | 处理方式 |
| --- | --- | --- |
| Dashboard | 今日练习 | 重构为主工作台 |
| Materials | 客户材料 | 保留并增强材料记忆 |
| Practice | 今日练习 / 练习流程 | 顶层入口弱化，作为核心流程承载 |

```text

```

## 8. 核心体验闭环

### 8.1 标准使用流程

```text
进入今日练习
  -> 查看系统推荐练习
  -> 选择材料或使用最近材料
  -> 选择练习目标、客户角色和声音包
  -> 进入实时对话
  -> 结束并生成复盘
  -> 保存表达和记忆
  -> 系统更新下一次推荐
```

### 8.2 会前准备流程

```text
进入客户材料
  -> 上传或选择客户材料
  -> AI 生成材料摘要和客户可能问题
  -> 点击“用这份材料练习”
  -> 选择会议目标
  -> AI 扮演客户进行实时沟通
  -> 复盘材料覆盖度、问题回答和表达质量
```

### 8.3 轻量复习流程

```text
进入表达库
  -> 系统推荐今天 5 句需要复习的表达
  -> 用户逐句跟读或进入短对话练习
  -> 系统更新掌握状态
```

### 8.4 长期记忆流程

```text
练习结束
  -> AI 提取可保存记忆
  -> 用户确认保存
  -> 记忆进入材料、用户、客户或弱点分类
  -> 下一次练习按相关性调用
```

## 9. 页面 PRD

## 9.1 今日练习

### 9.1.1 页面目标

用户打开网站后，不需要理解所有功能，只需要回答一个问题：今天我应该练什么？

### 9.1.2 页面核心结构

1. 今日主推荐
2. 三个次级入口
3. 最近材料
4. 最近复盘摘要
5. 本周重点

### 9.1.3 今日主推荐

主推荐占据首屏核心位置，包含：

```text
推荐练习标题
推荐原因
练习目标
客户角色
使用材料
预计时长
主按钮：开始今日练习
```

示例：

```text
今天建议你练：
技术负责人 · 隐私与部署异议 · 预计 8 分钟

推荐原因：
你最近在回答隐私问题时解释偏长，且没有主动推进下一步试点。

按钮：
开始今日练习
```

### 9.1.4 次级入口

首页只保留三个次级操作：

1. 上传客户材料
2. 练一个常见异议
3. 复习 5 句表达

### 9.1.5 禁止事项

1. 不在首页平铺全部功能。
2. 不放大量说明性文字。
3. 不同时出现多个同等级主按钮。
4. 不把技术配置、API 状态等内容放在首页首屏。

### 9.1.6 验收标准

1. 用户进入首页 5 秒内能看到“开始今日练习”。
2. 首页最多只有一个视觉最强主按钮。
3. 用户最多 2 次点击可以进入一次练习。
4. 首页必须显示推荐练习的原因。

## 9.2 创建练习流程

### 9.2.1 页面目标

把当前较重的练习配置，改成 3 步式选择，降低用户开始成本。

### 9.2.2 流程结构

```text
第 1 步：这次想练什么？
第 2 步：让 AI 扮演谁？声音是什么风格？
第 3 步：要使用什么材料或记忆？
```

### 9.2.3 第 1 步：练习目标

选项：

1. 客户问答
2. 演示讲解
3. 异议处理
4. 方案会议
5. 60 秒快速表达

每个选项使用一句中文解释，不展示复杂参数。

### 9.2.4 第 2 步：客户角色与声音包

第 2 步分为两个轻量选择：客户角色画像和 AI 声音包。客户角色决定 AI 问什么、怎么追问；声音包决定 AI 听起来是什么性别、性格和声音风格。

当前 Rokid 商务场景默认客户角色：

1. 企业买家
2. 技术负责人
3. 采购经理
4. 渠道合作伙伴
5. 高管决策者

角色卡片应展示：

```text
角色名称
关注点
沟通风格
可能追问方向
```

声音包卡片应展示：

```text
声音包名称
性别
性格
声音风格
语速
适合场景
```

预设声音包：

| 声音包 | 性别 | 性格 | 声音风格 | 语速 | 适合场景 |
| --- | --- | --- | --- | --- | --- |
| Ava 友好买家 | 女 | 友好、耐心、愿意配合 | 清晰温和，压力较低 | 中等 | 新手练习、客户问答、产品介绍 |
| Serena 企业决策者 | 女 | 专业、克制、结果导向 | 冷静商务，表达简洁 | 中等偏慢 | 企业采购、方案会议、ROI 讨论 |
| Ethan 技术负责人 | 男 | 理性、细节导向、追问较多 | 稳重清晰，技术感强 | 中等 | 技术参数、集成、部署、安全问题 |
| Marcus 高管客户 | 男 | 直接、高压、时间敏感 | 低沉坚定，节奏较快 | 中等偏快 | 高管简报、价值陈述、快速推进 |
| Vivian 挑剔采购 | 女 | 谨慎、怀疑、关注成本 | 犀利干练，追问强 | 偏快 | 价格、竞品差异、优缺点、谈判 |
| Noah 渠道伙伴 | 男 | 开放、务实、合作型 | 亲和自然，商务轻松 | 中等 | 渠道合作、市场支持、售后政策 |

声音包是产品层配置，实际接入时需要映射到实时语音模型支持的具体 voice id。如果当前模型不支持完全一致的音色，前端仍保留声音包选择，后端使用最接近的可用 voice，并在调试信息中记录映射关系。

### 9.2.5 第 3 步：材料与重点

用户可以选择：

1. 最近材料
2. 指定上传材料
3. 不使用材料，直接练通用场景
4. 使用系统记忆生成训练

训练重点标签：

1. 商业价值
2. 隐私安全
3. 试点推进
4. 简短回答
5. 探索式提问
6. 产品演示表达
7. 应用场景说明
8. 优缺点对比
9. 竞品差异
10. 产品参数解释

### 9.2.6 高级设置

高级设置默认折叠，包含：

1. 对话难度
2. 纠错强度
3. 是否开启实时提示
4. 是否启用长期记忆
5. 是否启用保密模式

### 9.2.7 验收标准

1. 用户无需阅读说明即可完成创建。
2. 每一步最多显示 5 个主要选项。
3. 默认值可直接开始练习。
4. 创建流程在移动端可单手完成。

## 9.3 实时对话房间

### 9.3.1 页面目标

让用户感觉自己正在和一个 AI 客户通话，而不是在操作复杂的录音工具。

### 9.3.2 核心状态设计

页面只显示一个主状态：

```text
对话中
```

不再把用户暴露在“聆听中”“回复中”“处理中”等技术状态里。

### 9.3.3 页面布局

核心区域：

1. AI 客户角色头像或角色卡
2. 当前状态：对话中
3. 计时器
4. 主操作按钮：静音、结束并复盘

辅助区域：

1. 最近 2-3 轮对话
2. 轻量提示面板
3. 材料要点抽屉
4. 当前目标提醒

### 9.3.4 轻量提示设计

提示必须帮助用户继续表达，而不是打断用户。

提示类型：

1. 下一句可以这样说
2. 可以追问客户的问题
3. 更商务的表达
4. 材料相关要点
5. 异议回答框架

提示展示原则：

1. 默认不超过 2 条。
2. 每条不超过 20 个英文词。
3. 有中英文对照。
4. 支持一键收藏到表达库。
5. 不遮挡主通话区域。

### 9.3.5 对话字幕

字幕默认模块只显示最近 2-3 轮英文内容，不展示中文翻译，避免实时对话时分散注意力。

默认字幕模块结构：

```text
AI 客户：英文内容
你：英文内容
```

默认字幕模块整体可点击。用户点击默认字幕模块后，展开为完整字幕模块。

完整字幕模块展示：

```text
AI 客户：
英文内容
中文翻译

你：
英文内容
```

完整字幕模块交互规则：

1. 完整字幕模块展开后保持持续展示。
2. 用户可以在完整字幕模块内滚动查看历史对话。
3. 完整字幕模块右上角固定展示“折叠”按钮。
4. 用户点击“折叠”后，回到默认字幕模块。
5. 展开和折叠状态不影响实时对话连接。
6. 默认字幕和完整字幕都只把用户说的话展示为英文，不默认展示用户内容的中文翻译。
7. 点击某一句用户英文后，可以查看句子评价、中文意思和是否保存到表达库。

点击用户某句英文后可查看：

1. 中文意思
2. 句子评价
3. 如果表达不自然，展示更自然的英文
4. 如果表达已经自然，展示肯定反馈
5. 是否保存到表达库

### 9.3.6 结束对话

点击“结束并复盘”后：

1. 停止实时连接。
2. 保存 transcript。
3. 触发复盘生成。
4. 进入复盘加载页。

加载页应展示：

```text
正在整理你的对话
正在找出最值得复习的句子
正在更新你的长期记忆
```

### 9.3.7 错误状态

常见错误：

1. 麦克风权限未开启
2. Relay 连接失败
3. AI 已连接但没有音频输出
4. 网络中断
5. 模型服务异常

错误展示必须是用户能理解的中文，不暴露底层技术术语。

示例：

```text
没有检测到麦克风权限，请允许浏览器使用麦克风后重试。
```

### 9.3.8 验收标准

1. 用户进入页面后能明确知道是否正在通话。
2. 页面主状态只出现“对话中”。
3. 结束按钮始终可见。
4. transcript 不抢占主视觉。
5. 错误提示能引导用户下一步操作。

## 9.4 客户材料

### 9.4.1 页面目标

把材料页从“文件管理”升级为“会前准备中心”和“长期记忆来源”。

### 9.4.2 页面结构

1. 上传材料
2. 最近使用材料
3. 材料摘要
4. AI 提取的客户可能问题
5. 材料相关表达
6. 记忆状态

### 9.4.3 上传后体验

上传成功后不只显示文件名，应立即生成：

1. 材料核心摘要
2. 客户可能关心的问题
3. 适合练习的会议目标
4. 相关 Rokid 产品表达
5. 可保存为长期记忆的内容

页面提供两个主操作：

```text
生成会议准备卡
用这份材料开始练习
```

### 9.4.4 材料记忆

材料不应是一次性的。系统需要记录：

1. 材料主题
2. 产品/方案关键词
3. 客户行业
4. 客户痛点
5. 常见问题
6. 使用时间
7. 最近一次练习表现
8. 是否允许进入长期记忆

### 9.4.5 材料保密

每份材料需要显示记忆状态：

```text
仅本次使用
可用于后续练习
已加入长期记忆
保密材料
```

用户可以在材料详情页切换保密设置。

### 9.4.6 验收标准

1. 上传材料后必须给出下一步行动。
2. 材料详情页必须能直接开始练习。
3. 用户能看到材料是否进入长期记忆。
4. 保密材料不能自动进入长期记忆。

## 9.5 复盘

### 9.5.1 页面目标

把复盘从“数据结果页”改成“下一次进步的起点”。

### 9.5.2 一级模块命名

当前一级模块“进步”改名为“复盘”。

首阶段可以保留 `/progress` 路由，但 UI 文案必须改为“复盘”。

### 9.5.3 复盘首页

复盘首页包含：

1. 最近一次练习总结
2. 本周最重要弱点
3. 已保存表达
4. 已保存记忆
5. 下一次推荐练习
6. 历史练习记录

### 9.5.4 单次复盘页结构

单次复盘页先展示 30 秒结论：

```text
这次最好的地方
这次最需要改的地方
下一次建议练什么
```

然后用 tabs 展开：

1. 总评
2. 句子升级
3. 异议处理
4. 材料覆盖
5. 表达收藏
6. 记忆确认

### 9.5.5 句子升级

句子升级不应机械地改写用户所有句子。系统需要先判断用户原句是否已经自然、清晰、适合当前商务场景。

如果用户原句需要优化，每条句子升级包含：

```text
你说的英文
中文意思
更自然的英文
为什么这样更好
适用场景
保存到表达库
```

如果用户原句已经自然，则不展示“更自然的英文”，而是展示肯定反馈：

```text
你说的英文
中文意思
评价：这句话已经自然、清楚，适合当前场景
做得好的原因
适用场景
保存到表达库
```

句子升级模块应同时支持两种状态：

1. `needs_upgrade`：需要给出更自然英文。
2. `already_natural`：不改写，直接肯定用户表达。

### 9.5.6 记忆确认

复盘页必须包含“可保存记忆”区域。

示例：

```text
AI 发现这些内容可能对以后练习有帮助：

1. 用户在隐私问题上容易解释过长。
2. 用户更适合先用一句结论，再解释原因。
3. 最近练习的客户材料重点是企业部署和实时翻译。

按钮：
保存全部
逐条编辑
不保存
```

### 9.5.7 验收标准

1. 复盘页首屏必须有明确结论。
2. 用户能一键把句子保存到表达库。
3. 用户能确认哪些内容进入长期记忆。
4. 复盘页必须提供下一次练习入口。

## 9.6 表达库

### 9.6.1 页面目标

表达库不是静态资料库，而是用户每天可以复习和调用的表达训练工具。

### 9.6.2 页面结构

1. 今天建议复习的 5 句
2. 最近复盘保存的表达
3. Rokid 高频产品表达
4. 异议回答表达
5. 我的个人表达
6. 材料专属表达

### 9.6.3 表达卡片

每张表达卡包含：

```text
英文表达
中文含义
适用场景
难度
掌握状态
练这句
收藏 / 取消收藏
```

### 9.6.4 表达练习

点击“练这句”后进入轻量练习：

1. 跟读
2. 替换关键词
3. 放入真实对话
4. 生成 3 个相似表达

### 9.6.5 分类建议

Rokid 当前分类：

1. 开场与会议目标
2. 产品价值表达
3. 产品应用场景
4. 产品优点与缺点
5. 竞品差异与替代方案对比
6. 产品详细参数
7. 技术与部署
8. 隐私与安全
9. 试点与下一步
10. 价格与 ROI
11. 异议处理
12. 跟进邮件表达

### 9.6.6 验收标准

1. 表达库首页必须有“今天建议复习”。
2. 每条表达必须有中文解释。
3. 表达可以从复盘页保存进入。
4. 表达可以被练习流程调用为提示。

## 9.7 记忆中心

### 9.7.1 页面目标

让用户知道 AI 记住了什么，并能管理这些记忆。

### 9.7.2 入口位置

记忆中心放在：

```text
复盘 -> 我的记忆
```

设置页也提供入口：

```text
设置 -> 隐私与记忆
```

### 9.7.3 记忆分类

1. 个人画像
2. 说话习惯
3. 长期弱点
4. 材料记忆
5. 客户/场景记忆
6. 常用表达偏好
7. 学习偏好

### 9.7.4 记忆字段

每条记忆包含：

```text
id
用户 id
场景包 id
记忆类型
标题
内容摘要
来源
来源时间
置信度
重要性
最近使用时间
使用次数
是否可用于 AI 提示
是否敏感
过期时间
创建时间
更新时间
```

### 9.7.5 记忆调用策略

练习开始前，系统根据以下因素选择记忆：

1. 与当前场景相关性
2. 与当前材料相关性
3. 最近使用时间
4. 重要性
5. 用户确认状态
6. 敏感等级

建议权重：

```text
相关性 45%
最近性 15%
使用频率 15%
重要性 15%
置信度 10%
```

每次实时对话最多注入 10-20 条短记忆，避免 prompt 过长。

### 9.7.6 隐私原则

1. 默认不长期保存原始音频。
2. 默认保存结构化摘要，而不是完整敏感 transcript。
3. 长期记忆必须让用户可见、可编辑、可删除。
4. 保密材料默认不进入长期记忆。
5. 用户可以开启“仅本次练习模式”。
6. 用户可以暂停记忆功能。

### 9.7.7 验收标准

1. 用户能看到 AI 记住了什么。
2. 用户能删除单条记忆。
3. 用户能关闭某条记忆的 AI 调用权限。
4. 练习结束后能确认是否保存新记忆。

## 9.8 设置

### 9.8.1 页面目标

设置页只处理偏好、隐私和技术配置，不抢占主流程。

### 9.8.2 设置项

1. 当前场景包
2. 语言水平
3. 纠错强度
4. 实时提示偏好
5. 记忆开关
6. 保密模式
7. 模型连接状态
8. 麦克风测试

### 9.8.3 验收标准

1. 非技术用户能看懂设置项。
2. 模型/API 状态不出现在首页主流程。
3. 记忆和隐私设置入口清晰。

## 10. 场景包扩展能力

### 10.1 背景

当前产品是 Rokid 商务英语定制系统，但未来需要支持：

1. 日常英语口语练习
2. 社交英语口语练习
3. 人工智能行业英语练习
4. 面试英语练习
5. 旅行英语练习
6. 其他企业定制场景

因此，不能把所有页面、提示词、角色和表达都写死为 Rokid。

### 10.2 Scenario Pack 定义

每个场景包是一组配置，控制产品的内容、角色、练习目标、复盘维度和表达库分类。

建议结构：

```ts
type ScenarioPack = {
  id: string;
  name: string;
  shortName: string;
  targetUser: string;
  primaryGoal: string;
  homepageCopy: {
    title: string;
    subtitle: string;
    primaryCta: string;
  };
  practiceGoals: PracticeGoal[];
  personas: Persona[];
  voicePacks: VoicePack[];
  promptTemplates: PromptTemplates;
  phraseCategories: PhraseCategory[];
  objectionCategories?: ObjectionCategory[];
  reviewRubric: ReviewRubric;
  memorySchema: MemorySchema;
  moduleToggles: ModuleToggles;
};
```

### 10.3 Rokid 商务场景包

场景包 id：

```text
rokid-overseas-sales
```

主目标：

```text
帮助 Rokid 海外销售与解决方案人员完成英文客户会谈。
```

默认模块：

1. 客户材料
2. 实时客户模拟
3. 异议处理
4. 产品表达库
5. 会后复盘
6. 长期记忆

默认角色：

1. 企业买家
2. 技术负责人
3. 采购经理
4. 渠道合作伙伴
5. 高管决策者

默认声音包：

1. Ava 友好买家
2. Serena 企业决策者
3. Ethan 技术负责人
4. Marcus 高管客户
5. Vivian 挑剔采购
6. Noah 渠道伙伴

复盘维度：

1. 流畅度
2. 清晰度
3. 商务推进力
4. 产品价值表达
5. 异议处理
6. 材料覆盖度
7. 句子自然度

### 10.4 日常英语场景包示例

场景包 id：

```text
daily-english
```

模块差异：

1. 不需要客户材料。
2. 不需要异议库。
3. 表达库分类改为生活主题。
4. AI 角色改为朋友、店员、邻居、同事等。
5. 复盘维度更关注自然度、词汇、听说反应。

### 10.5 AI 行业英语场景包示例

场景包 id：

```text
ai-industry-english
```

模块差异：

1. 可使用行业文章或产品资料。
2. 表达库聚焦 AI 技术和商业化。
3. AI 角色包括投资人、客户、工程师、媒体采访者。
4. 复盘关注技术解释能力和观点表达。

### 10.6 验收标准

1. 新增一个场景包不应大规模复制页面。
2. 首页文案、练习目标、角色、声音包、复盘维度可以由配置驱动。
3. Rokid 相关文案不能硬编码到通用组件中。
4. 表达库和记忆需要带 `scenarioPackId`。

## 11. AI 与提示词设计

### 11.1 模型职责

当前模型职责建议：

1. Gemini Live：只用于实时语音对话。
2. DeepSeek：用于材料分析、准备卡、复盘、表达提取、记忆总结等文本任务。

### 11.2 实时对话 Prompt 输入

实时对话开始前，系统需要组装：

1. 当前场景包
2. 用户练习目标
3. AI 客户角色
4. AI 声音包及其模型 voice 映射
5. 当前材料摘要
6. 相关长期记忆
7. 用户本次训练重点
8. 对话规则

### 11.3 轻量提示 Prompt

轻量提示必须短、可说出口、与当前上下文相关。

输出格式：

```json
{
  "suggestions": [
    {
      "type": "next_sentence",
      "en": "A practical next step would be to run a small pilot with one team.",
      "zh": "一个实际的下一步，是先让一个团队做小范围试点。",
      "reason": "用于推进下一步"
    }
  ]
}
```

### 11.4 复盘 Prompt

复盘需要输出结构化结果：

1. 总结
2. 亮点
3. 主要问题
4. 句子升级
5. 表达收藏建议
6. 记忆候选
7. 下一次练习建议

### 11.5 记忆 Prompt

记忆提取不能保存太多细节，应提取可复用的学习信号。

记忆候选分为：

1. `speaking_habit`
2. `weakness`
3. `material_context`
4. `customer_context`
5. `phrase_preference`
6. `learning_preference`

## 12. 内容与文案规则

### 12.1 中文优先的操作体验

网站的标题、按钮、提示、错误信息和引导文案应以中文为主。

英文保留在：

1. 真实练习内容
2. 英文表达
3. 英文 transcript
4. 英文句子升级
5. 客户模拟对话

### 12.2 文案原则

1. 按钮用动词开头。
2. 中文提示短句化。
3. 不使用复杂英语解释功能。
4. 不出现“配置参数”式表达。
5. 不把用户错误描述成技术错误。

示例：

| 不推荐 | 推荐 |
| --- | --- |
| Generate prep card failed | 准备卡生成失败，请稍后重试 |
| Select persona | 选择 AI 扮演的客户 |
| Start realtime session | 开始实时练习 |
| Progress | 复盘 |

## 13. 视觉与交互规范

### 13.1 视觉方向

整体风格应是：

```text
专业、轻量、可信、像私人教练，而不是后台管理系统。
```

### 13.2 色彩

建议使用：

1. 主色：科技青绿，用于主按钮和关键状态。
2. 辅助色：深灰蓝，用于标题和信息层级。
3. 背景：浅灰白，保持安静。
4. 警示色：琥珀或红色，仅用于风险和错误。

避免：

1. 大面积深色背景。
2. 过多渐变。
3. 大面积紫蓝色科技风。
4. 过多卡片堆叠。

### 13.3 布局

1. 每个页面只保留一个主行动。
2. 页面首屏必须回答“我现在应该做什么”。
3. 重要流程使用分步引导，而不是长表单。
4. 移动端优先展示主任务，次要内容折叠。
5. 不使用卡片套卡片。

### 13.4 组件

建议组件：

1. 顶部场景切换器
2. 今日练习推荐卡
3. 三步练习创建器
4. 通话状态面板
5. 轻量提示浮层
6. 材料摘要卡
7. 复盘结论卡
8. 表达卡
9. 记忆确认列表

### 13.5 可访问性

1. 所有按钮点击区域不小于 44px。
2. 图标按钮必须有 aria-label。
3. 不依赖颜色传达唯一信息。
4. 键盘可以访问核心流程。
5. 移动端不能出现横向滚动。

## 15. 关键指标

1. 首页进入后点击“开始今日练习”的比例。

### 15.2 使用指标

1. 单次练习平均时长。

## 16. 开发里程碑

### Milestone 1：信息架构与导航重构

目标：

1. 一级导航改为“今日练习 / 客户材料 / 表达库 / 复盘”。

目标：

1. 首页展示一个主推荐练习。

1. 首页首屏只有一个主 CTA。

目标：

目标：

1. 页面主状态改为“对话中”。

验收：

1. 页面不再出现“聆听中 / 回复中”作为主状态。
2. 结束并复盘按钮始终可见。
3. 错误提示使用中文用户语言。

### Milestone 5：客户材料页重构

目标：

1. 上传后直接生成可行动结果。
2. 材料详情支持“生成准备卡”和“用这份材料练习”。
3. 显示材料记忆状态。

## 18. 风险与应对

### 18.1 风险：重构范围过大

应对：

按 milestone 分阶段实施，先重构导航和首页，再做练习房间和记忆。

### 18.2 风险：记忆功能引发隐私担忧

应对：

默认让用户确认长期记忆，不自动保存敏感材料；提供删除和禁用入口。

### 18.3 风险：场景包抽象过早复杂化

应对：

第一阶段只做 TypeScript 配置，不急于做后台管理系统。

### 18.4 风险：实时语音体验仍受模型或 relay 影响

应对：

前端状态统一为“对话中”，技术状态放入调试区；错误提示用用户语言解释，并保留麦克风测试入口。

### 18.5 风险：首页推荐质量不稳定

应对：

第一阶段使用规则推荐和 mock 数据，后续再引入 AI 动态推荐。

## 19. 默认产品决策

1. 一级模块“进步”统一改为“复盘”。
2. `Objection Bank` 不再作为一级导航，但保留功能。
3. 首页命名为“今日练习”，而不是“Dashboard”。
4. 实时对话主状态只显示“对话中”。
5. 材料默认不进入长期记忆，用户确认后保存。
6. 记忆中心放在“复盘”模块下。
7. Rokid 是第一个场景包，不是唯一场景。
8. 当前阶段不做复杂场景包后台，用代码配置即可。
